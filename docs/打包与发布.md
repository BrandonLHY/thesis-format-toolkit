# 打包与发布

面向维护者：怎么从源码产出 exe、怎么发 Release。

---

## 打包 exe

```bash
pip install -r requirements.txt pyinstaller
python build_exe.py              # 打两种形态
python build_exe.py onedir       # 只打文件夹版
python build_exe.py onefile      # 只打单文件版
```

产物在 `dist/`：

```
dist/
├─ 论文格式改写器/                 ← 文件夹版（推荐）
│   ├─ 论文格式改写器.exe
│   ├─ _internal/                  （运行库，必须一起发）
│   └─ 使用说明.txt
└─ 论文格式改写器_单文件版.exe      ← 单文件版
```

---

## 两个版本怎么选

| | 文件夹版 | 单文件版 |
|---|---|---|
| 体积 | 约 39 MB（压缩后约 17 MB） | 16 MB |
| 启动速度 | 快 | 慢几秒（每次自我解压） |
| 兼容性 | **最好** | 依赖可写的临时目录 |
| 建议 | **首选发布这个** | 图省事时提供 |

**发给别人时，文件夹版要把整个文件夹压缩后发**，不能只发里面的 exe。

## 打包时踩过的三个坑

这三条都是实测踩到的，改打包配置时务必保留对应处理：

### 1. `docx/templates` 必须显式打进去

PyInstaller 的 `--collect-all docx` 与 `--collect-data docx` **都不会**带上
`docx/templates/default.docx`。缺了它，程序一调用 `Document()` 新建文档就报：

```
PackageNotFoundError: Package not found at '...\docx\templates\default.docx'
```

`build_exe.py` 里用显式 `--add-data` 解决（见 `docx_template_add_data()`）。
打包后**一定要跑一次自检**，这项会被「端到端改写」检查抓到。

### 2. 单文件版要指定解压目录

单文件 exe 默认把自己解压到系统临时目录。若对方机器临时目录不可写（企业策略、
磁盘满、杀毒软件拦截），会直接报错打不开：

```
Could not create temporary directory!
```

`build_exe.py` 里用 `--runtime-tmpdir _MEI_temp` 让它解压到 exe 自身目录。
**代价**：exe 必须放在有写权限的目录，放 `C:\Program Files` 下会再次失败。

### 3. 打包产物要验证，不能只看「打包成功」

打包成功不等于能运行。每次打包后必须做这两步：

```bash
# 1. 自检（会验证依赖完整、端到端改写、界面构建）
dist/论文格式改写器/论文格式改写器.exe --selftest

# 2. 看生成的报告
cat dist/论文格式改写器/自检报告.txt
```

`--selftest` 在没有控制台的 `--windowed` 模式下也能用——它把结果写到
`自检报告.txt`。

## 发布 Release

exe 不进 Git 仓库（`.gitignore` 已排除 `dist/` 与 `release/`），走 GitHub Releases。

### 步骤

1. 打 tag 并推送：
   ```bash
   git tag v1.0.0
   git push origin v1.0.0
   ```

2. 打包出压缩文件：
   ```bash
   mkdir -p release
   # Windows PowerShell
   Compress-Archive -Path "dist\论文格式改写器\*" `
     -DestinationPath "release\thesis-format-toolkit-v1.0.0-windows.zip"
   ```

3. 在 GitHub 上建 Release：
   - 仓库页面右侧 → **Releases** → **Create a new release**
   - Choose a tag：选刚推的 `v1.0.0`
   - Release title：`v1.0.0 首个版本`
   - 说明里**必须附上源码链接**（GPL-3.0 的义务，见下）
   - 把 zip 拖进附件区上传
   - **Publish release**

## GPL-3.0 的分发义务

本项目用 GPL-3.0，**对外分发二进制时必须提供对应源码**。发 Release 时：

- [ ] Release 说明里写明源码位置，例如：
      `对应源码：https://github.com/BrandonLHY/thesis-format-toolkit/tree/v1.0.0`
- [ ] 附件里包含 `LICENSE`（GPL-3.0 全文），或说明仓库内已有
- [ ] `使用说明.txt` 里提到本程序是 GPL 自由软件

`build_exe.py` 生成的 `使用说明.txt` 已包含基础说明；若需要在其中加入许可证
声明，改 `build_exe.py` 的 `write_readme()`。

## 发布检查清单

每次发版前逐项确认：

- [ ] `python run_all_selftests.py` 全部通过
- [ ] `python build_exe.py` 打包成功
- [ ] 打包产物 `--selftest` 通过
- [ ] 手动双击 exe，用一份真实论文验证一遍
- [ ] 确认 `dist/`、`release/` 没有被 `git add` 进去
- [ ] tag 名字与 Release 说明里的源码链接一致
- [ ] Release 附件可下载且能解压运行
